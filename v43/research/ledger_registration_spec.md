# Prospective forecast registration v1
Existing Python operations.py scores closed-hour first-touch records. This addition creates a compatible ledger entry only when an operator explicitly submits a forecast. No model promotion or auto-conversion of descriptive levels. Use actual UTC issue clock, next UTC hour boundary, confirmed hourly anchor, source CSV SHA256, snapshot hash, model version and explicit target, invalidation and observation cap. Reject stale anchors (>2 hours), mismatch with confirmed close, nonpositive prices, duplicate IDs, invalid revisions and synthetic sources. No historical registration. Existing ledger lines immutable; use append and exclusive lock. Registration does not promise a trading entry; observation cap is evaluation-only. Tests use synthetic times; no live forecast created. Workflow currently runs existing scoring step hourly; verify real workflow delivery independently. Full-path and extreme scoring remain separate.
